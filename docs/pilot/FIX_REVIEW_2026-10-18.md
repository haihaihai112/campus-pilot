# 2026-10-18 测试反馈修复

此文为对应阶段的历史记录；后续实现状态与本次发布验证以 README 和 docs/PUBLICATION.md 为准。
依据本机五个脚本人设的测试报告、持久化轮次及 MCP/A2A 记录定位问题。五个人设不代表五名真实学生，也不计入实际采用人数。原始对话、账号和报告留在被 Git 忽略的目录。

## 问题与处理

| 问题 | 核对结果与修复 |
|---|---|
| 非空待办回答被引用校验拦截 | 待办中已有来源 ID，但本轮 evidence 为空。校园 MCP 现在按本人待办引用的 ID 返回当前配置中能核实的来源，助手载入后再校验。未知 ID 仍不能作为依据，没有整体豁免引用校验。 |
| 单条个人待办被转为整单入学规划 | 原来只有计划保存与待办状态更新，没有单条创建工具。增加 request_todo_create 预览，经原确认机制调用内部 MCP create_personal_todo；不直接开放模型写入。 |
| 删除请求复述历史空列表 | 常见待办查询、删除请求读取本轮最新列表。删除明确答复暂不支持，并展示最新事项；没有实现删除，也不声称已经删除。模型其他个人查询同样被要求重新调用工具。 |
| 说“保存”却再次规划 | 对明确、完整的确认或拒绝短句，应用处理本会话已展示的唯一操作。引用文本、日期确认、带其他条件的句子不作为通用写入授权；多个旧操作无法唯一确定时转为按钮确认。新清单使同会话未执行旧清单过期，避免累积可执行草案。 |
| REST 与 Gradio 表现不同 | 原报告使用了不同历史，不能据此认定两条入口实现不同。两条入口继续共享引擎；明确的入学清单请求统一委派 A2A，保留用户上下文，未知条件由规划 Agent 追问。同输入、同为空历史的双入口回归比较了实际清单项目。 |
| 脚本取不到 Gradio State 中的请求编号 | 保留服务端身份校验，把轮次编号改为运行详情中的只读普通输出。脚本可取得 turn_id 并调用既有确认接口；编号本身不赋予权限，外账号确认仍拒绝。 |
| 失败内容污染后续历史 | 引用校验拒绝的最终回答以实际展示的安全回复替换，避免未展示的错误回答成为后续历史事实。完整工具调用与结果对仍保留。 |

单条个人待办支持标题、可选截止日期和明确起止时间的个人提醒。无提醒时只创建待办；日期和时区在预览及写入时验证。项目内日历与 ICS 不等于主动通知，外部推送仍未接入。个人事项没有伪造校规来源，截止日不会变成学校政策。

写入使用服务端账号、事务和固定 operation_id；重复确认返回同一结果。拒绝、过期操作不执行。个人提醒导出也覆盖了没有关联计划的情况。内部统计增加 action_completed / action_rejected；人工复核成功写入时仍须存在持久化成功结果，反馈和任务正确率继续分开。
