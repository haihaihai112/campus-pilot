# 体验说明与扩邀条件

## 给体验者的说明

CampusPilot是个人开发的邀请体验项目，面向武汉理工大学2026级本科入学事务。当前使用4份2026-10-11官方网页快照，可能不完整或过期；不是学校业务系统。组织者在发出邀请前填写体验地址、起止日期、资料更新状态、反馈与删除联系渠道。

每人一个账号，请处理本人当前实际遇到的问题。不要输入身份证、密码、录取通知书照片或其他敏感材料。可以只咨询，不要求保存待办或创建日历。规划是草案；点击确认后才会保存个人待办，明确指定的个人提醒也不是校方预约。外部日历尚未绑定，不能承诺手机主动推送提醒。

对每轮回答可自愿选择“有帮助/无帮助”并补充意见。无答案、错误追问、等待过久和保存失败都欢迎记录；组织者记录匿名问题、预期和实际行为、时间、错误类型及本地turn/action编号，不要求学生贴敏感截图。反馈评价与答案正确性分别检查。

## 阶段放行表

| 阶段 | 进入条件 | 退出/扩大条件 | 当前状态 |
|---|---|---|---|
| 需求确认 | 5名自愿对象 | 5份匿名访谈、2—3个有依据场景、阻断缺口已明确 | 待访谈 |
| 本地准备 | 已选场景 | 来源适用性复核；30条案例独立审核；先5条真实模型记录；隔离/拒绝/重复/旧版本/重启通过 | 工具与草案准备，实际复核待做 |
| 远程验证 | 单任务实测费用、服务器报价和总预算已确认 | 单进程主应用+3内部服务；HTTPS登录、备份恢复、5/10人模拟与少量真实端到端验证 | 未部署 |
| 5人试用 | 上述条件满足 | 核心咨询/规划/保存通过；关键缺陷修复；费用、等待、失败可追踪；仍有真实需求 | 未开始 |
| 累计15—20人 | 5人阶段放行 | 再审质量、费用、等待、隔离和真实需求 | 未开始 |
| 累计50—70人 | 上批放行 | 持续记录实际提交、完成与反馈，分别统计 | 未开始 |

每批记录：账号创建人数、真实需求提交人数、人工复核完成任务人数、成功确认保存人数/操作次数、自愿反馈人数、当前未解决问题、Token费用及预算余额。测试账号、fixture、开发者和历史演示单列。只有后续主动使用记录存在，才描述持续使用。

发现越权读取/写入、未经确认写入或重复写入：立即停止扩邀并暂停相关写操作；保存最少必要证据，停用受影响账号或停止主应用，核对数据库与幂等记录；修复并回归后再放行。无法确认写入结果时先核对记录，避免用户反复新建。

回滚前停四服务并备份当前数据。还原必须到新runtime目录，先核对哈希、账号隔离、待办/日历与重复确认，再切换配置；不得直接覆盖当前数据库，也不能仅回滚代码后假定数据兼容。恢复后复核中断轮次，不自动重跑模型或写操作。

简历用语以证据为准：“邀请X名学生参与，Y名提交真实需求，完成Z次确认保存”。目前X/Y/Z均无真实使用证据，不填写推测值。
