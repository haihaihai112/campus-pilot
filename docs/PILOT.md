# CampusPilot 邀请体验部署

## 本地与远程的区别

`AUTH_MODE=demo` 无登录，个人记录全部使用演示身份；只用于本机展示。`AUTH_MODE=pilot` 要求邀请账号和三份不同的私有服务凭据，启动时拒绝演示凭据。

`campus init-pilot` 只创建一次 `.env.pilot`，同名文件存在时拒绝覆盖。默认 `COOKIE_SECURE=false` 仅支持本地 HTTP；给远程体验者使用时，必须由反向代理提供 HTTPS，并改为 `COOKIE_SECURE=true`。

主应用单进程运行，内部三个服务不向外部发布端口。`campus all --host 0.0.0.0` 仅让主应用监听共享地址，内部服务仍绑定回环地址。优先使用 HTTPS 反向代理转发到默认的回环主应用；应用仅信任受控代理。

## Docker

已有 Compose 的主应用仅映射 `127.0.0.1:8010`；内部服务不发布端口。示例：

```powershell
docker compose --env-file .env.pilot up --build -d
docker compose --env-file .env.pilot run --rm app campus accounts add student01
```

镜像本轮未构建验证。宿主机 `.env.pilot` 不会复制到镜像，Compose 注入其配置。容器账号保存在 `app_data` 卷，需要备份账号、助手、校园和规划服务各自的数据卷。

## 限额与恢复

默认每账号每分钟 240 个 HTTP 请求、每小时 20 个新对话、最多 2 个待处理对话；全局最多 32 个待处理对话、4 个处理中的对话。HTTP 请求计数包括前端轮询，调整时要留出轮询预算。

HTTP、对话和登录次数为 SQLite 固定窗口计数，重启不清空当前窗口。固定窗口在边界附近可能出现突发，这是首轮体验版本的已知限制。响应超额返回 429 与 Retry-After。

账号密码采用 PBKDF2-HMAC-SHA256、随机盐和 600000 次迭代；数据库仅保存登录 token 的 SHA256。账号停用会撤销全部登录。浏览器 Cookie 为 HttpOnly、SameSite=Strict；跨站写请求被拒绝。令牌不是模型工具参数。

对话运行中重启会标为中断，已有数据保留，不静默重跑写入。登录会话在未过期且账号有效时仍可恢复。各账号自己的 ICS 在下载时重新检查登录，不生成共享静态导出文件。

## 使用与评测

先邀请 5—10 名体验者检查流程与误答，稳定后逐步扩大到 50—100 名；这是推广安排，不是已达成规模，也不是 100 人同时在线的承诺。

真实模型调用需要运营者配置有效凭据并承担费用。fixture适合验收协议、隔离和事务，仅支持有限表达，不能替代真实模型体验。默认资料为武汉理工大学2026级本科公开快照，参考日期为当天北京时间；DEMO_DATE只用于显式历史重放。资料年份、模型模式和日期在页面分别展示。

v0.3.1默认使用独立runtime-whut-2026目录。旧.env.pilot不自动改写，旧合成目录不覆盖。容器升级采用新的Compose项目名创建独立数据卷。未知校方时段只保存待办，明确的个人提醒才生成日历。

`campus stats` 输出脱敏汇总，分别统计 fixture/live 的提交用户、对话状态、模型报告 Token、完成处理耗时和自愿反馈。耗时不含等待队列；反馈可能有样本选择偏差，不作为准确率。
