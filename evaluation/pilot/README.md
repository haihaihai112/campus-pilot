# 30条评测草案与独立审核

cases-30.json包含30条待审核案例，smoke5为5条首轮候选。标签由实现助手根据本地快照拟定，全部pending_independent_review。尚未独立标注、运行真实模型或确认当前需求；不能称作已完成30条独立评测。

先完成访谈与场景选择：这些案例覆盖已有机制和已知边界，不能替代学生的实际问题。独立审核者应未参与本次实现，先看官方资料、适用范围与问题，再自行写期望答案；与草案对照并记录分歧、修订、审核日期及审核者匿名编号。无法获得有效官方依据的案例标记资料不足，不强行给确定答案。

每例检查：引用语义是否支持结论、年份/学生类型、必要追问、未知内容、过期节点、工具参数、确认前后写入与归属。不能只匹配关键词或以引用存在当正确。系统安全案例的code_refs是行为依据，官方text_anchors不是权限授权。历史日期仅在隔离fixture目录重放，单列为历史演示；实际当前任务按当天北京时间。

先在配置、有效价格与支出预算确认后，人工运行smoke5的5条真实模型案例。记录实际问题、回答、引用、工具/失败、各轮Token、等待/处理耗时、任务完成与是否保存。出现关键安全问题先修复，不扩大。先5条通过并复核成本后，再决定是否运行其余25条；多轮场景的“5条案例”可能需要超过5次模型请求。

结果模板results-template.json保持空白。per_case包含case_id、model_config（不含key）、outcome、semantic_support、tool_execution、queue_ms、processing_ms、calls、failure_reason、reviewer。先做逐例判断再汇总分母；资料不足、未跑、拒绝与执行失败分别记录。反馈满意度、人工任务完成率和独立答案正确率分别报告，不互相替代。

安全/恢复案例宜先fixture执行现有自动化测试，再用少量live检验自然语言触发效果。自动化测试通过不代表这些人工语义案例已通过。
