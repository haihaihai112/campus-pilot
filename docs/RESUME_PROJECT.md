# CampusPilot 项目经历

CampusPilot｜新生入学事务助手

技术栈：Python、LangGraph、FastAPI、MCP、A2A、RAG、SQLite

基于高校公开入学资料，构建知识咨询、个人办理清单及确认保存闭环。

- 通过LangGraph编排原生工具调用，MCP复用知识与校园工具，A2A管理独立规划Agent的追问、继续、取消及计划交付；规划服务中断时保留问答和事项查询。
- RAG采用父子分块与TF-IDF/BM25加权融合，按学生类型、入学年份和校区过滤证据，保留官方来源及快照版本；区分规则清单与个人提醒，校方时段未知或节点过期时返回明确缺口。
- 实现邀请账号和服务端身份注入，通过来源重校验、服务端快照、版本校验、SQLite事务及幂等键控制确认写入；104项自动化测试通过，覆盖真实跨进程协议、账号隔离、提醒冲突及重启恢复。

## 面试展开点

1. 双Agent的收益是任务生命周期和故障隔离，不声称必然提高准确率。
2. 从合成精确排程迁移到真实资料后，为什么要把未知办理时间和个人提醒分开？
3. 绿色通道为什么不能与“缴费后才能报到”写成同一强制依赖？
4. 事务、幂等键、版本和服务端快照分别解决哪类执行错误？
5. 模型不能决定查询身份，API及Gradio入口都要检查归属。

## 数字口径

104项为程序和协议测试，其中75项合成回归、29项真实资料专项；模型使用fixture，不是回答准确率。4份来源为本轮实际入库，11类模板不是学校已对接接口数量。旧86.7%合成检索指标不沿用。没有真实用户规模、校方合作、真实模型质量或50—100人负载成果。
